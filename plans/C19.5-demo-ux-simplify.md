# C19.5: Demo UX — Simple / Customize Split

**Phase:** Demo / Polish  
**Estimate:** 0.5–1 day  
**Depends on:** [C13](./C13-demo-playground.md) / [C13.5](./C13.5-demo-sessions.md); pairs with [C19](./C19-first-public-publish.md)  
**Suggested schedule:** **Immediately before** (or as the first workstream of) first npm publish — demo is the primary marketing surface  
**Priority:** High (publish-adjacent P1)  
**Status:** Complete  

---

## Goal

Reduce first-visit cognitive load on the GitHub Pages / Vite demo without removing power-user controls: default **Simple** surface (Scenario + Theme + always-visible Play), everything else one click away under **Customize**. Fix two concrete UX bugs: snippet always-open, and Tail vs Full history override confusion.

**Not in scope:** shipping `demo/` in the npm tarball (already excluded — see Packaging note); renaming the package; new chart API props; host wiring.

---

## Packaging note (confirmed — no code change)

`package.json` already has `"files": ["dist"]`. The published tarball is **build output only**. `demo/`, `tests/`, `plans/`, `spikes/` stay in git (Pages, contributions, history) and **never** reach `npm install`. Standard component-library practice — leave as-is. Document in C19 publish checklist as verified.

---

## Workstreams

### A — Simple vs Customize

1. **Simple (visible by default):** Scenario + Theme.  
2. **Play:** keep `RrgPlaybackControls` first-class and always visible below the chart (not buried in Customize).  
3. **Customize (collapsed by default):** one disclosure for the rest of today’s flat control row — Viewport, Labels, Tail / Full history, Size, Always labels, Tail fade, Loop playback, Accessible summary, Advanced, Copy overrides entry points as today (nested details may remain).  
4. Nothing removed — only progressive disclosure. Preserve `data-testid`s where practical; add tests for open/closed Customize if URL/session needs a new `customizeOpen` flag (optional; default closed).

### B — Snippet on demand

1. Wrap the component snippet `<pre>` in a `<details>` (same pattern as Advanced / Perf / Copy overrides).  
2. **Default closed** (`showSnippet` / `snippetOpen` default `false`).  
3. Keep “Copy component snippet” button usable without expanding (copy still works from current snippet string).

### C — Tail vs Full history clarity

1. Group Tail length + Full history as one control cluster with short helper copy, e.g. “Full history overrides Tail length.”  
2. Keep existing disable behavior (`tailLength` disabled when `fullHistoryTail`).  
3. Optional: when Full history is on, show muted/strikethrough or “overridden” next to the Tail input — not just a bare disabled field.

### D — Tests / hygiene

- Update demo unit / Playwright expectations if they assume open snippet or flat control layout.  
- No production `src/` changes unless a shared util is needed (unlikely).  
- Demo-only Vitest coverage for any new session/URL flags.
