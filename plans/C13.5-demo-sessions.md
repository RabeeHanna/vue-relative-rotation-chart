# C13.5: Demo Session Persistence

**Phase:** Demo / Polish (mini unit)  
**Estimate:** 0.5 day  
**Depends on:** [C13](./C13-demo-playground.md) playground + Tier 4 controls  
**Suggested schedule:** Immediately after C13 follow-ups; before [C14](./C14-public-release.md)  
**Priority:** High for demos — prevents “change one knob, lose the rest”  
**Status:** Complete (implementation + unit tests)

---

## Goal

Persist **all user-visible demo configs** in a browser **session** (`sessionStorage`) so:

1. Changing any one control does **not** reset unrelated controls  
2. Refresh / soft navigation keeps the playground state for the tab  
3. Shareable URL sync remains; session fills gaps and holds non-URL fields

---

## Problem today

- Changing **scenario** forces `viewportMode` / `labelMode` to that fixture’s suggestions (wipes user choices)  
- Playback `speed`, CSS theme pickers, generator fields, BYO JSON, panel open state are not all durable across reload  
- URL sync covers many knobs but not the full visible surface

---

## Locked decisions

1. **Storage:** `sessionStorage` key `vrrc-demo-session` (tab-scoped; not cross-tab localStorage)  
2. **Load merge order:** package defaults → session → URL query (URL wins when a param is present)  
3. **Scenario change:** only switches series / `source=preset`; **never** overwrite viewport, labels, theme, speeds, etc.  
4. **Persist everything visible**, including:
   - All Tier 1–4 / Advanced / Power-user controls  
   - Playback: `speed`, `selectedDate` (and loop / min / max / speedMode already in controls)  
   - UI chrome: `showSummary`, `advancedOpen`  
   - Generator + BYO text (not the applied override series body unless still in textarea)  
5. **Do not** persist hover readout or ephemeral `copyStatus`  
6. Custom/generated **applied** series: keep “data not in link”; session may keep `source` + textarea / generator params so user can re-apply
